# Financial Report Module Guide

## 一、模块定位

`financial_report` 不是被削弱的旧财报系统，而是从单一 Streamlit 财报工具升级为 FinancialResearch 金融研究集成平台中的核心模块。

它负责把财报资料从“原始 PDF / 公告材料”推进到“可追踪、可解释、可回测、可修正的研究判断”。当前工程骨架已经把 PDF 解析能力外置给 Parse Lab，但财报分析方法论继续保留在 FinancialResearch 内。

`financial_report` 的目标职责包括：

- 财报和辅助材料上传
- Parse Lab PDF 解析结果接入
- 文档类型识别
- 主时序财报与辅助材料区分
- 财务表格、正文段落和指标信息抽取
- 财报分析
- 预测
- 回测
- 预测修正
- 长期跟踪
- 决策支持

## 二、完整流程

财报研究不是一次性摘要，而是一套长期闭环流程：

```text
PDF / 财报资料输入
-> Parse Lab 解析
-> 文档类型识别
-> 主时序财报与辅助材料区分
-> 表格 / 正文 / 指标抽取
-> 财报分析
-> 预测
-> 回测
-> 预测修正
-> 长期跟踪
-> 决策支持
```

其中，Parse Lab 负责解析候选和质量标记；FinancialResearch 负责研究流程、字段抽取、分析、预测、回测、修正和决策支持。

## 三、财报分析 10 大模块

项目内所有公司分析都应遵循统一骨架，保证不同行业、不同时间点之间可对比。

### 1. 行业定位

分析前必须先判断：

- 一级分类
- 二级分类
- 三级分类

然后回答：

- 公司商业模式是什么
- 赚谁的钱
- 靠什么赚钱
- 是平台制、项目制、产品制、服务制还是授权制
- 产业链处于上游、中游还是下游
- 议价能力从哪里来
- 同类可比公司有哪些

行业定位是整个研究的第一步。分类不清，后面的财务指标权重和风险判断都会偏。

### 2. 宏观环境

必须结合对应财报期的宏观背景作为 benchmark，例如：

- 贸易战
- 新冠疫情
- 美元利率
- 汇率
- 中美关系
- 国内政策
- 国内经济情况
- 行业周期
- 商品价格
- 监管变化

宏观分析必须写清影响路径：

- 如何影响收入
- 如何影响成本
- 如何影响需求
- 如何影响融资

最后判断公司是否跑赢宏观、是否跑赢行业。

### 3. 公司概况

回答：

- 公司做什么
- 主营业务如何拆分
- 收入结构如何分布
- 产品、区域、客户类型占比如何
- 业务模式是一次性还是持续性

### 4. 成本结构

重点分析：

- 原材料
- 人力
- 研发
- 渠道
- 折旧摊销
- 物流
- 财务费用
- 利用率、良率、单位成本

并回答：

- 核心成本驱动是什么
- 成本压力来自哪里
- 是否具备转嫁能力

### 5. 客户结构

重点分析：

- 客户类型
- 客户集中度
- 前五大客户依赖
- 区域分布
- 单一区域风险
- 政府客户、大客户、平台依赖

### 6. 盈利模式

这是核心模块之一。必须回答：

- 公司到底靠什么赚钱
- 哪些业务是真正利润来源
- 高毛利板块来自技术、品牌、资源、渠道还是会计口径
- 盈利是一次性还是可重复
- 盈利能力是否可持续

### 7. 资金流向

重点分析：

- 经营现金流
- 投资现金流
- 融资现金流
- 资本开支
- 并购扩张
- 分红和回购
- 偿债安排

这一步用于纠正“利润表很好看，但现金流很差”的误判。

### 8. 未来展望

应提取和分析：

- 管理层重点
- 未来增长驱动
- 新产品、新市场、提价、效率提升等路径
- 下期关键验证指标

### 9. 护城河

应分析：

- 技术
- 品牌
- 渠道
- 规模
- 资源
- 网络效应
- 切换成本

并判断护城河状态：

- 增强
- 稳定
- 削弱

### 10. 风险 + 预期

风险必须区分：

- 生存性风险
- 经营性风险

并给出监测指标，例如：

- 库存周转
- 毛利率
- 应收占比
- 合同负债
- 在手订单
- 资本开支
- 现金短债比

预期必须输出：

- 下一年趋势
- 关键拐点
- 触发条件
- 情景切换条件

## 四、行业定位规则

所有财报分析必须先完成一级、二级、三级行业分类。

不同细分行业的财报分析重点不同，不能所有公司套同一个模板。例如：

- 矿业：资源量、品位、现金成本、资本开支
- CRO / CDMO：在手订单、客户结构、项目进度、产能利用
- 半导体：产能利用率、库存、ASP、下游需求
- 医疗器械：认证、渠道、毛利率、集采影响
- 消费：品牌力、渠道、促销、库存、复购

统一的是研究骨架；变化的是模块权重和关键指标。

## 五、主时序财报与辅助材料区分

主时序财报包括：

- 年报
- 半年报
- 季报
- 其他正式定期报告

主时序财报才预期包含资产负债表、利润表、现金流量表。它们用于形成 actuals 口径、时间序列、预测映射和回测基准。

辅助材料包括：

- 业绩新闻稿
- 业绩公告
- 业绩简报
- 电话会议纪要
- 投资者演示材料
- 并购公告
- 其他经营更新材料

辅助材料不应因为缺少三大表被判为解析失败。它们主要用于补充解释、验证趋势、提取管理层表述和经营线索，不能替代正式财报进入主时序 actuals。

## 六、预测、回测、修正机制

FinancialResearch 的目标不是生成单次报告，而是形成长期研究系统。

预测必须具备：

- 历史财报基础
- 当前已知信息
- 统计模型或可解释假设
- AI 解释层
- 预测快照
- 实际值对照
- 偏差归因
- 修正日志
- 历史反馈

未来财报发布后，需要对过去预测做回测，判断偏差来自：

- 宏观变化
- 行业变化
- 公司自身变化
- 预测模型失效
- 分析框架遗漏
- 原始解析或字段抽取质量问题

回测后要修正预测模型和判断逻辑，形成长期跟踪分析。

## 七、决策支持

最终目的不是只总结财报，而是支持研究判断，例如：

- 是否值得继续研究
- 风险是否上升
- 盈利能力是否改善
- 现金流是否恶化
- 公司是否出现生存风险
- 当前预期是否需要修正
- 哪些指标需要下期重点跟踪
- 哪些结论需要人工复核或外部验证

## 八、数据结构和质量原则

财报研究输出应优先结构化，JSON 优先。

质量原则：

- 信息不足可以保留 `unknown` / `insufficient_evidence`
- 不强行编造缺失信息
- 数据来源必须可追溯
- 表格、正文、人工修正、外部验证需要区分来源
- 解析质量不够时进入 `candidate_only` 或 `human_review`
- 主时序财报与辅助材料必须分开存储和判断
- 财务字段进入分析前必须保留来源页、来源类型、置信度和验证状态

建议字段级来源信息包括：

- `value`
- `unit`
- `period`
- `source_pdf`
- `source_page`
- `source_type`: `text` / `table` / `human_corrected` / `external_validation`
- `source_engine`
- `confidence`
- `validation_status`
- `evidence_text`
- `table_id`

## 九、与 Parse Lab 的边界

Parse Lab 是独立 PDF 解析服务。

Parse Lab 负责：

- PDF 解析
- 表格候选
- 正文候选
- 页面级 attribution
- table quality flags
- candidate-only / needs-human-review 等解析质量信号

FinancialResearch 的 `financial_report` 模块负责：

- 财报研究流程
- 文档类型判断
- 字段抽取
- 财务分析
- 预测
- 回测
- 修正
- 决策支持
- Dashboard / 工作台展示

边界原则：

- FinancialResearch 不 import Parse Lab 内部 parser
- FinancialResearch 不直接调用 Marker / MinerU / PaddleOCR / pdfplumber / PyMuPDF
- FinancialResearch 通过 HTTP API 或解析输出接入 Parse Lab
- Parse Lab 产出可信候选，FinancialResearch 决定研究语义和业务使用方式

## 十、当前工程状态

当前新架构已经把旧 Streamlit 单体拆为 FastAPI 平台骨架。`financial_report` 仍处于模块化接入阶段，已有 Parse Lab submit / poll / manifest / quality gate 等基础接口；正式字段抽取、metrics、forecast、backtest 和 report generation 尚未接入生产流程。

这份文档用于保留财报分析模块的方法论，不代表所有能力已经实现完成。
